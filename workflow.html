web2html workflow

Orchestrator 2.9.0 · live site → Paper → semantic static HTML. This is the human map of every board step: what it is, what it needs, which scripts run, what must exist before mark done. Agents still follow SKILL.md and the step accordion on the live board.

First action of any run: start the live board. If it does not open, stop.

python3 $SKILLS/web2html/scripts/pipeline-progress.py start /path/to/templates/<project>

start writes and opens that folder’s pipeline.html, quarantines leftover rebuild/*.html, and never overwrites the spec web2html/pipeline.html.

Second action (2.26.0): the run intake. mark 1.1 active refuses until it is recorded.

python3 $SKILLS/web2html/scripts/run_config.py intake /path/to/templates/<project> \
  --source none|/abs/path/to/html-export --speed full|fast
python3 $SKILLS/web2html/scripts/run_config.py show /path/to/templates/<project>

  • Speed. fast forces auto checkpoints and 1600/390, skips the Design Library, and still stops at 3.4. full keeps the human stops. full + --checkpoints auto is refused.

Global rules

  • Never skip a numbered step (1.1 → 3.4). pipeline-progress.py skip fails on required steps. Capture Tool is leftover live hover — mark 1.4 active opens the stamped tab; pipeline-progress.py open-capture re-opens it. It is not a 1.4 done-gate. Phase 4 is optional after 3.4 — write qa/phase-4-opted.json or qa/phase-4-skipped.json. Phase 5 is optional after 4.4 — write qa/phase-5-opted.json or qa/phase-5-skipped.json.
  • mark --step <id> --status active|done at every boundary. mark cannot open 2.1+ while 1.1–1.4 are unfinished.
  • New run: start. Continued session (2 or 3): resume . --at <step> --owner <session>. start force-resets the board and throws a run in flight away (Pitfall #179).
  • Homepage only through 3.4 (/). Extra routes stay out of 1.2. Phase 4 is Paper-only. Phase 5 binds the site into astro/ after 4.4 opt-in: 5.1 pulls Header / Footer / components once from the 3.4 polish, 5.2 authors only each page's <main>. 5.5 is the one post-3.4 href exception.
  • No local HTTP server. Preview is file:// — in Orca's browser when the probe says orca reachable (the board, 2.4 review, 3.4 compare + report, 5.6 routes; WEB2HTML_BROWSER=default keeps Chrome), else Chrome. Phase 5 relativizes astro/dist so built pages open on file://. The agent verifies with astro build, never astro dev; the human may run npm run preview.
  • Do not write rebuild/*.html from a scrape, Firecrawl, Tailwind CDN, or memory. Gate first:
python3 $SKILLS/web2html/scripts/rebuild_write_gate.py /path/to/templates/<project>
python3 $SKILLS/web2html/scripts/rebuild_write_gate.py /path/to/templates/<project> --allow index           # 2.1+
  • One rebuild/. Extra rebuild-semantic/ trees fail verify-rebuild-trees.py.
  • Silent shell for 20s (especially the 1.3 library mine): kill the PID and rerun with live logs. Do not wait minutes.
  • Reviewers may only write qa/agent-findings/. The controller owns Paper, rebuild/, the board, and canonical qa/ receipts.

Homepage vs all pages

The board is two bands. 1–3 are the required homepage run (/ only). 4–5 are optional all-pages work that starts only after 3.4 opt-in. They reuse the signed homepage tokens and chrome. They do not recapture /, do not mine a second Design Library, and do not rewrite 2.3 geometry.

Three sessions, two handoffs

A run spans three sessions so the model can change per phase. 2.0 and optional 5.0 are recommended on the strong tier — those are the phases that author HTML or Astro bodies no earlier artifact contains. 1.0, 3.0, and 4.0 are recommended on the operator tier: every step there either lands on a script that opens the artifacts and compares them, or stops for a human. The tier is advice, never a gate — no script checks the model, and a session runs on whichever model the operator chose without stopping to ask for a switch.

mark --step 1.4 --status done and mark --step 2.4 --status done release the controller lease and print a copy-ready prompt for the next session, also written to qa/handoff-2.0.md / qa/handoff-3.0.md. 4.4 opted in writes qa/handoff-5.0.md. Copy it into a fresh session on the right tier.

Relay (mid-session). When mark prints RELAY armed, finish the current unit and run relay . --owner <held>. It writes qa/handoff-<step>.relayN.md, releases the lease, and on a reachable Orca opens a terminal for the same agent and sends the prompt; otherwise it prints the block. The successor runs resume . --at <step> --owner session-2b. A relay is a change of agent, never a human stop.

A continued session never runs start. start force-resets the board and quarantines ship HTML — it is for a new run only. Sessions 2 and 3 resume:

python3 $SKILLS/web2html/scripts/pipeline-progress.py resume . --at 2.1 --owner session-2

That loads existing progress, refuses if predecessors are unfinished, claims the controller lease under the new owner, and rewrites the board HTML without opening a new tab. The live board was opened once by start. Full detail in references/model-routing.md. Pitfalls #179 #180 #191.
